- Curation lead, discourse, supply and alert rules stay pure in `curation.ts`, `discourse.ts`, `supply.ts` and `alerts.ts`; `forecast.server.ts` only loads data and stores components, so UI, MCP and tests read the same numbers.
- `/api/public/ingest-wire` accepts either the crawler secret (sampler payloads) or the managed cron credential with an empty body, so the existing schedule keeps working.
- Are.na stays hard-off (`ARENA_ENABLED` in `sources.ts`) because its acceptable-use policy forbids automated harvesting; nothing may write `arena` rows.
- External source polling (Product Hunt) keeps conditional-request cursors in the private `source_cursors` table and stays within a per-run request budget.
- Missing forecast components count as the cohort mean and are recorded per row; never backfill absent historical signals in the backtest.
- Showcase math stays pure: rebrand detection/read lines in `rebrands.ts`, tag-space PCA/k-means in `vibe.ts`, card selection/layout in `chart/model.ts` + `chart/card.ts`; `*.server.ts` only load and store, so UI, MCP and tests share one result.
- Chart PNGs use the pure-JS rasterizer (`chart/raster.ts` + generated `glyphs.gen.ts` from `scripts/build-glyph-atlas.py`) because WASM renderers can't be verified on the hosted runtime; `chart_cards` stores each week's model so published cards stay immutable.
- Derived outputs (taste refresh, brief, vibe map, chart card) run only after the forecast is stored ok and never fail it; `vibe_points` keep one run's projection per quarter.
- Failed forecast runs store a sanitized `stage: code message` (`runErrorText` in `forecast-run.ts`) in `forecast_runs.error` so health can show why; a stale or missing crawl drops crawl components, never the run.
- Wide JSON scans read by the anonymous client page below 1000 rows and select JSON paths, because each page must finish within the anonymous statement timeout.
- All model calls use `aiClient()` from `ai-provider.server.ts`, resolved before `ai_reserve` so price table, `ai_usage.provider` and the call agree; request mapping/parsing stays pure in `ai-provider.ts`, and a misconfigured provider fails closed with no fallback.
- Job health rules stay pure in `health.ts` over the anonymous `health_facts()` facade; the public endpoint and status bar share `health.server.ts`, and the platform blocks cron introspection, so callback cut-offs are inferred from interrupted or stuck runs.
- Trait display names, dimensions (FONT/COLOR/LAYOUT/VIBE) and the five stage words live only in pure `labels.ts`; UI, alerts, chart cards, brief context and MCP (`withLabels` in the shared `json()`) import it, and stored text is rewritten only at render time so history rows stay untouched.
- Info cards, the glossary panel and tour copy share pure `glossary.ts`; UI headings reference entries as `g="id"` so `glossary.test.ts` can scan for missing ids, and methodology anchors come from `methodology.ts`.
- TODAY lines are built by pure `today.ts` from public SELECT reads in `todayQuery` (no AI per view); tour state is pure `tour.ts` with injected storage and an in-memory fallback.
- The Digest is pure `digest/issue.ts` (`issueModel`) and `digest/trait.ts` (`traitModel`) over rows read by `digest/digest.server.ts` for one ISO week (brief run, previous run, that week's events), so old issues never change with newer data; editorial copy helpers live in `digest/copy.ts` and names still come only from `labels.ts`.
- Site thumbnails live in the private `site-thumbs` bucket (workspace blocks public buckets) and are served by `/thumbs/<path>` only while a visible `site_thumbs` row exists; intake and opt-out share crawler-secret auth before body reads, pure checks in `thumbs.ts`, and an injectable store in `thumbs-ingest.server.ts`. The hosted runtime has no verified image encoder, so the crawler sends final WebP sizes.
- Digest/explainer share images reuse the chart primitives (`chartPrims`, `renderPrimsSvg`, rasterizer) with `LIGHT_PALETTE`; editorial CSS sits in `@layer components` under `.digest` so the terminal is untouched.
- The shared-password site gate runs in `src/server.ts` via pure `src/lib/gate.ts` before SSR (default-deny, explicit `OPEN_PATHS` list tested against every route file), because a route-level redirect would still ship page data and meta; an empty hash constant disables it.
- Agency workflow logic stays pure in `src/lib/agency/` (watch rules, feed items, `auditModel`); the `watchlists` table is service-role only behind injectable stores in `watch.server.ts`, so ids can't be enumerated and tests run against memory stores. View id, edit token (stored only as SHA-256) and feed token are separate 128-bit capabilities; the feed route is the one human-content OPEN_PATHS entry.
- The forecast ledger is pure `ledger/ledger.ts` (one `LEDGER_RULE` constant, selection, next-quarter call, resolution, hit rate) over the append-only `forecast_calls` table; `ledger/store.server.ts` records and resolves after the stored run through `nonFatal`, and DB triggers make call fields immutable, so the record can't be rewritten and can never fail a forecast.
- Embeds are server routes returning self-contained HTML from pure `embed/embed.ts` (no scripts or cookies; three viewBox sizes keep axis text legible from 280–800 px); `frame-ancestors *` is set only there, and `/embed/` is the only framing-allowed OPEN_PATHS entry.
- MCP keys are owner-issued and stored only as SHA-256 in service-role `mcp_keys`; `handleMcp` takes injectable deps (resolver with ~30 s cache, per-key limiter, usage counter) so anonymous behaviour stays unchanged and tests run in memory; the admin endpoint reuses crawler-secret auth before reading the body.
- What is shown by default is decided only in pure `tiers.ts` (static visible/decision judgments + coverage/moves from the stored run); every default surface, chart selection, Digest movers and alert candidates filter through it, so collection stays wide and display narrow.
- Composites (`composites.ts`) enter the forecast only through `forecastSiteTraits` and are scored in their own next-wave cohort and kept out of crossings and backtests, so existing traits' numbers never change.
- Momentum index and Confidence are display-only (`momentum.ts`, `signals.ts`) over stored forecast fields; the terminal, explainers, /what-we-show and MCP (`signal-index.ts`) share one snapshot, read with useSuspenseQuery so SSR and hydration agree.
- Sandbox forecast runs use `DEV_RUN` (`scripts/forecast-dev-run.ts`): no brief, alerts, ledger, derived outputs or pruning, because preview and the live site share one database.
- `ia.ts` is the one map of sections, terminal tabs, keys, aliases and surfaces; `ia.test.ts` walks `src/routes` and the legacy panel list, so every new route file or panel needs a SURFACES entry.
- `/` is always Read (Live); the terminal lives at `/terminal` and old `/?panel=…` and `/trait/<key>` links redirect through `legacyTerminalSearch` / route `beforeLoad`, so stored alert links stay valid without rewriting rows.
- Object pages (signal, brand, pattern) come from pure models (`digest/trait.ts`, `brand.ts`, `patterns.ts`) carrying `blocks: OBJECT_BLOCKS` and render through `components/read/ObjectPage`, so the four-block order cannot drift; stories are pure adapters in `stories.ts` over rows loaded by `read.server.ts` with a short in-memory TTL (no AI per view).
- The sector lens is a per-route optional `?sector=` param plus device storage (`sector-lens.ts`, failures read as All); there is no root validateSearch, and scoped signal numbers fall back to All with a note below the coverage threshold.
