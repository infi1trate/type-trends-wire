- Pitches are judged only from the build's own plan and rule refusals (`pitchView` → pure `pitch.ts`); a pitch never adds a candidate, changes a score or publishes, and `pitches`/`pitch_verdicts` are insert-only and service-role only behind the editor key.
- Quiet changes are pure `quiet.ts` (stored as `move` rows told apart by a `quiet:` id, because the stored type list is a fixed check); outside-news absence uses the strict news matcher over every wire item, but only publications on the wire's source list (`wire-sources.ts`) count as outlets. A page change that follows a confirmed homepage change of the same kind within 30 days is never quiet: it becomes a fact on the brand's own story (candidate facts, plus an append-only fold onto the stored published or held story).
- A quiet page change's picture comes from `surface_crops` through `pagePair` and is carried as `page-from:`/`page-to:` source ids (read back on the story page), and capture dates for "How we know" come from one pure `capture-dates.ts` shared by the facts-built line and the writers' sheet, so the picture rule, the deck and both date lines cannot disagree.
- Numbers lines that state a share, stage or momentum carry the date of the run they came from, and a later run that changes a cited signal's stage adds one dated update line within 14 days; both come from pure `as-of.ts` (no model, copy-lint checked) and the stored story text is never rewritten.
- Rewrite requests are pure `rewrite.ts` (open until the writer's next version after the request; requested stories go first via `requestedFirst`) over append-only `rewrite_requests` filed only by the door's `rewrite`; kept out of `writer.ts` so the standards checklist fingerprint does not move.
- Story-page update lines read only the cited signals' rows of the two runs (`citedStages`), never whole runs, and stay in the deferred lead so the page's first byte waits only on the story head.
- Stage-change and crossover candidates compare like with like (`readComparable` in `candidates.ts`, thresholds in `types.ts`): the earlier run's homepages read, from the row's latest-quarter sample, must be a set share of the later run's and above a floor, else the pair is recorded as more homepages read and no story is built, because a rise in reading is not a change.
- A crossover must be new to its sector (`sectorHistory` in `candidates.ts`): the later run's own well-read earlier quarters decide it and supply the named "up from" quarter, never the earlier run's one reading; quarters are read only for rows passing every other crossover check (`crossoverQuarterNeeds` → `forecastRowQuarters`), so the shared run-row read stays latest-quarter only.
- An AI-read field whose value changed on more than a quarter of a sector's homepages read in both forecast runs is "not steady" (pure `steady.ts`, reads in `steady.server.ts`, read only for crossovers and stage changes passing every other check); those candidates are refused and recorded, measured fields are never subject, and the data desk's unsteady findings live in `newsroom/steady-findings.ts` so the standards checklist fingerprint does not move.
