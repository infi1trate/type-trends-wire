- No screenshot or icon picture is ever fetched, stored or drawn by the app; the crawler sends only counts, text openings and measured screenshot colours. Listing text is kept for measurement and shown only as aggregates or short linked quotes.
- `/api/public/ingest-listings` (crawler secret, 256 KB, ≤25 apps per post, up to 8 parts per category) only stores: pure checks in `contract.ts`, an injectable `ListingStore` in `ingest.server.ts`, no follow-up work or marks.
- Text is stored once: `app_listings` per app (about, `about_changed_at` set when the text changes), `app_listing_versions` per version (notes; corrected in place), `app_listing_weeks` slim per week (later post replaces, identical writes nothing, 26 weeks kept, other apps of the week are never deleted because a category arrives in parts).
- An app removed from the icon study stays removed here: ingest refuses ids removed in `app_icons` or `app_listings`, and `icon_remove` marks the listing removed and blanks its about and version notes.
- No page, loader, MCP tool or job reads these tables yet; `isolation.test.ts` fails if `src/components` or any route but the ingest route imports `src/lib/listings/`.
