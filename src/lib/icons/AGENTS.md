- App icons are stored and shown only as measured colours (palette), name, maker and App Store link; no icon picture is ever fetched, stored or drawn by the app, because Apple's terms allow icon pictures only beside a store badge to promote the app.
- `app_icons` is service-role only behind an injectable `IconStore` (`ingest.server.ts`); the crawler-secret `/api/public/ingest-icons` stores one snapshot per ISO week per category (later post replaces, unchanged writes nothing, 26 weeks kept), and a removed app keeps its rows with `removed_at` so it is refused forever and every reader read filters it out.
- An icon ground, category counts and leans come only from pure `measure.ts` (mixed is never a ground, lead or lean; ties are kept as ties), so the study, its check and tests share one reading.
- The icon study (`data-stories/app-icons.ts`) is checked through `withheld()` with its own `ICONS_SHOWN` switch, reads `app_icons` only while that switch is on, and draws the existing swatch strip as equal cells (`cells`/`lit`/`links` on a drift band); a series whose every study is withheld is not listed, so hidden studies leave no trace on /data.
- A removal (`icon_remove`, `art_remove`) goes through `removal.server.ts`: it clears the taking server's memory copies and rewrites the stored study copies at once, and study-copy jobs drop input cached before the newest removal, because a per-request removal check would add a read to every reader request.
