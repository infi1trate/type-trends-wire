- The desks' rules stay pure in `copy.ts` (lints), `standards.ts` (checklist, second-reader prompt and parser), `chief.ts` (placement prompt and after-call enforcement) and `review.ts` (order of work, caps, fallbacks); `review.server.ts` only loads, calls the gateway and records, and every desk decision goes through the door as its desk, so tests replay the whole pass with fake I/O.
- A story the engine would run is stored held awaiting review and published only by the editor in chief's (or the owner's) `restore` after a standards pass newer than its last text or correction; a failed or capped desk call falls back to engine order with the reason recorded, so a failing desk never stops the day's stories.
- Desk prompts are versioned in `golden/versions.ts` with score files from frozen fixtures; the gate compares cases both versions ran, because a fixture re-run is limited by the model-call budget.
- News, graphics and data desks keep their rules pure in `news.ts`, `graphics.ts` and `datadesk.ts` (candidates, line checks, picture decisions, findings, backtest); `*.server.ts` only load, make the one capped call (`caps.ts`) and record through the door, and a failed or capped call leaves the rule's result standing with the reason recorded.
- The product loop's rules stay pure in `design-review.ts` (pages, widths, measures, budgets, breaches, the vision prompt and move enforcement), `queue.ts` (statuses and the order), `build-gate.ts` (the gate's checks, calling the living-design `gate()`) and `engineering.ts` (health problems by stable key); `*.server.ts` only load, store append-only rows and file through the door, so the outside browser job and engineering sessions are held to the same rules as tests.
- Share-image and study-chart checks run only in their own scheduled passes (`passes.ts` rules, `passes.server.ts` I/O, `/api/public/jobs/desk-passes`) from stored records with unique-slot start rows and finish rows, never in the job tail, because computing a study from raw history reads megabytes per item and the tail has no time to spare; the news desk runs in the wire ingest's job before the story build, and job holds are derived from `job_hold`/`job_release` desk-log rows.
- Story review runs only in its own scheduled pass (`review-pass.ts` rules, `review-pass.server.ts` I/O, `/api/public/jobs/review-passes`) over facts sheets the build stores in `review_sheets`, never in the job tail, because loading the build's context for a review reads megabytes and the tail has no time; every standards review stores the checklist's code fingerprint (`checklist-fp.gen.ts`, written by `scripts/newsroom-docs.ts`) so a checklist fix re-checks recent checklist holds once.
- The news desk's beat is enforced in code (`offBeat` in `news.ts`) as well as the prompt, so a model pick off the beat is dropped before it is stored.
- Holds are read only from stored edits and reviews by pure `holds.ts`: a hold through the door is never offered to a pass and only a door `restore` releases it, while the editor in chief's own pass hold is re-offered by `offerAgain` (`chief.ts`); out-of-time steps wait up to six passes, counted from finish rows, because time is not a reason to publish.
- Publisher and scout rules stay pure in `publisher.ts` (package checks, draft limits, audience shape) and `scout.ts` (sources register seeded in code, candidate checks); `*.server.ts` only load, make the one weekly call (`weekly-call.server.ts`, logged in `desk_calls_weekly`) and store append-only rows, and no posting or library-adding code exists, because outbound posts and new brands stay the owner's.
